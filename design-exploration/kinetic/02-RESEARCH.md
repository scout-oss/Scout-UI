# Stage 2 — Inspiration research

References were studied for their interaction mechanics (timing, physics,
interruptibility, restraint, implementation), not their look. Nothing below is
cloned; each entry ends with how Scout UI reinterprets the idea.

Method note: the essays were read in full; the studio sites were inspected over
HTTP and in the browser pane. Heavy WebGL sites could not be rendered while the
pane was hidden, so their analysis relies on their published case studies and
long-standing, well-documented behaviour.

## Techniques adopted

- Variable-font axes as an interaction channel (pressure → `wdth`/`wght`).
- Spring physics with velocity inheritance; CSS `linear()` spring easings.
- Shadow-separation lift; stacked-copy die-cut text (paper cut-line + ink
  outline via `paint-order: stroke fill`, which hides overlapping contours).
- Velocity-driven, self-stopping marquee instead of an ambient loop.
- One page-level IntersectionObserver; one-way reveals; "armed" pages so content
  is never hidden without JS.
- Gesture intent detection for touch.

## Techniques rejected (and why)

- **Scroll-linked position animations / scroll timelines**: fail the M17 "0
  running animations after settle" invariant; risk scroll-jacking feel.
- **WebGL / canvas hero**: bundle and battery cost, poor accessibility, and the
  package is DOM-first — the site should prove the DOM can do it.
- **Smooth-scroll libraries (Lenis etc.)**: scroll hijacking; explicitly out of
  scope.
- **Custom cursor site-wide**: the design system limits custom cursors to
  bounded canvases (§12); StickerCursor stays in its specimen.
